# Points of Interest (POIs)

**Namespace:** `osm.POIs` ·
**FFL:** `src/osm_geocoder/handlers/poi/ffl/osmpoi.ffl` ·
**Handlers:** `src/osm_geocoder/handlers/poi/poi_handlers.py` ·
**Backed by:** `src/osm_geocoder/handlers/combined/{combined_handler.py, plugins/population_plugin.py}` ·
**Tests:** `src/osm_geocoder/handlers/poi/tests/test_london_pois.py`

## Overview

The POI namespace extracts **settlements and place features** — cities, towns,
suburbs, villages, hamlets, countries — from a cached region PBF. Where
`osm.Amenities` answers "where are the restaurants" and `osm.Buildings` answers
"where are the footprints", `osm.POIs` answers "where are the *places*": the
`place=*` nodes that name and rank human settlements.

It is the one analysis namespace whose handlers delegate straight to the
**combined single-pass scanner** rather than to a dedicated extractor module: a POI
facet runs a `combined_scan(pbf, ["population"])` and then filters the resulting
GeoJSON down to the requested place type.

## How it works

Each POI event facet is generated by `_make_poi_handler(facet_name, return_param,
place_type, min_pop)` in `poi_handlers.py`:

1. **Cache check** — `cached_result` keyed on the input cache + `{place_type,
   min_population}`; a hit short-circuits.
2. **Scan** — `combined_scan(pbf_path, ["population"])` (from
   `combined/combined_handler.py`) runs the **population plugin** in a single
   `apply_file` pass and writes a `place`-tagged GeoJSON.
3. **Filter** — if `place_type != "all"`, keep only features whose
   `properties.place == place_type` (e.g. `"city"`); for `"all"` keep everything.
4. **Return** — an `OSMCache` struct under the facet's return parameter, carrying
   the filtered `output_path` and the feature count as `size`.

Data shape: `PBF → (population plugin) → GeoJSON place points → filter by place`.
The facet returns an `OSMCache` (not a feature-schema), so a POI result can be fed
straight back into other cache-consuming facets.

## Fan-out

**Single-task per region — no fan-out inside this namespace.** No `foreach` in the
FFL; extraction is one `combined_scan` pass over one PBF. Because several POI facets
(`Cities`, `Towns`, `Villages`, …) all derive from the *same* `population` scan,
running them against one region reuses the cached scan output rather than
re-reading the PBF each time — the amortisation is intrinsic to routing through the
combined scanner. Fleet parallelism across many regions is orchestrated by
higher-level atlas workflows.

## Filtering & attributes

Two-stage: the **population plugin** does the OSM-tag keep during the scan, then the
handler does a **Python equality filter on the `place` property**.

- Keep test (plugin): nodes carrying `place=*` (settlement nodes), with
  `population` read where present.
- Handler filter: `properties.place == place_type`, where `place_type` comes from
  the `POI_FACETS` table:

| Facet | `place_type` filtered | Return param |
|---|---|---|
| `Cities` | `city` | `cities` |
| `Towns` | `town` | `towns` |
| `Suburbs` | `suburb` | `towns` |
| `Villages` | `village` | `villages` |
| `Hamlets` | `hamlet` | `villages` |
| `Countries` | `country` | `villages` |
| `POI` | `all` (no filter) | `pois` |
| `GeoOSMCache` | `all` (no filter) | `geojson` |

The shared return-parameter names (`towns` for Towns+Suburbs, `villages` for
Villages+Hamlets+Countries) let those results be used interchangeably in workflows
that expect that grouping. `min_population` is threaded through the cache key but is
`0` for every wired facet today.

**Plain (non-event) facets** — `Volcanos(cache, elevation, active)`,
`Prisons(operator, capacity, securityLevel, gender)`, `NationalParks`,
`StateParks`, `Hospitals`, `Airports`, `Military(kind)` — declare richer typed
query signatures but have **no registered handler**. They are placeholders for
future agent implementations (per the README), not runnable today. Note the
`NationalParks`/`StateParks`/`Hospitals` names here are unrelated to the extractors
in `osm.Parks` / `osm.Amenities`.

## External libraries / binaries

- **`pyosmium`** (pip `osmium`) — via `combined_scan`; `poi_handlers` guards on
  `HAS_OSMIUM` and `register_poi_handlers` no-ops (registers nothing) when osmium is
  absent, so a runner without pyosmium simply doesn't advertise POI facets.
- No osmium-tool **binary** and no HTTP dependency on this path.

## Facets & workflows

| Facet | Kind | Effect/Cost | Purpose |
|---|---|---|---|
| `POI(cache)` | event | external / expensive | All place features (unfiltered) |
| `Cities(cache)` | event | external / expensive | `place=city` settlements |
| `Towns(cache)` | event | external / expensive | `place=town` |
| `Suburbs(cache)` | event | external / expensive | `place=suburb` |
| `Villages(cache)` | event | external / expensive | `place=village` |
| `Hamlets(cache)` | event | external / expensive | `place=hamlet` |
| `Countries(cache)` | event | external / expensive | `place=country` |
| `GeoOSMCache(cache)` | event | external / expensive | Convert cached OSM data to GeoJSON |
| `Volcanos` / `Prisons` / `NationalParks` / `StateParks` / `Hospitals` / `Airports` / `Military` | pure facet | — | **Declared only** — typed query placeholders, no handler |

All event facets take and return an `OSMCache`. There is no dedicated POI workflow
in this file; POI facets are chained inside composed workflows (cache → download →
POI extract → render).

## Cache / output

- The GeoJSON is produced by the population plugin under the combined scanner's
  output dir (`resolve_output_dir("osm-combined")`, i.e. local `FW_OUTPUT_BASE` or
  `s3://afl-cache/...` on the fleet); the POI handler returns that `output_path`
  inside the `OSMCache` and does not itself re-materialise a new file for the
  `"all"` case (it counts features in place).
- Result reuse via the sidecar `output_cache` keyed on cache + `{place_type,
  min_population}`.
- Maps come from `osm.viz.RenderMap`, not this namespace.

## Gotchas & notes

- **POIs return `OSMCache`, not a feature schema.** The `size` field carries the
  post-filter *feature count*, and `wasInCache` is `False` on a fresh extract —
  don't read `size` as a byte count.
- **`register_poi_handlers` is a hard no-op without pyosmium** — a runner that can't
  import osmium advertises zero POI facets (correct fleet behaviour: work routes to
  a capable host), but means "nothing happened" locally if osmium isn't installed.
- **The 7 plain facets are inert.** Referencing `Prisons`/`Volcanos`/etc. in a
  workflow will not execute — they are schema-only placeholders.
- **Name collisions across namespaces.** `osm.POIs.NationalParks` (placeholder) is
  distinct from `osm.Parks.NationalParks` (the real area extractor) — use the
  qualified name.
